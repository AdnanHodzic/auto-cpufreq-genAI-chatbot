------------------------------------------------------------------------------- ``` ### Problem When `platform_profile` is set in `auto-cpufreq.conf`, `auto-cpufreq` will set the platform profile every 2 seconds. On my machine (Lenovo Legion Pro 7i 16IRX8H), setting the platform profile will wake up the dGPU, I don't know exactly why it does this, but maybe the laptop firmware probes the state of the dGPU, causing it to wake. The dGPU takes 20 seconds to go from D0 to D3Cold, so it will stay at D0 forever if `auto-cpufreq` keeps changing the platform profile. ### Proposed solution Change [this line](https://github.com/AdnanHodzic/auto-cpufreq/blob/master/scripts/cpufreqctl.sh#L336) in `cpufreqctl.sh` to check if the platform profile we're trying to write is the same, if it is, just skip the operation. ```diff - echo $VALUE > $FWROOT/acpi/platform_profile + current_profile=$(cat $FWROOT/acpi/platform_profile) + if [ "$current_profile" != "$VALUE" ]; then + echo $VALUE > $FWROOT/acpi/platform_profile + fi ``` This will make `auto-cpufreq` not write to platform_profile, which allow the dGPU to enter deep sleep after 20 seconds. If this is OK, I can submit a PR. ### Feature Suggestion: `enforce_platform_profile` I also suggest adding a new configuration boolean: enforce_platform_profile. - If `true` (current behavior): `auto-cpufreq` will actively ensure the platform profile matches the config file at every loop interval. - If `false`: `auto-cpufreq` will set the profile once (e.g., on state change like AC/Battery), but will allow the user to manually override it (e.g., using the Fn + Q keyboard shortcut on Legion laptops) without the daemon immediately forcing it back. If the feature is approved, I am happy to work on it.
