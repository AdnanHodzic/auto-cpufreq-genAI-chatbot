@lucasleocs I was about to ask if this be related to what was merged as part of #972 ... But then I see error seems to occurs due to a broken/mismatched APT package dependency on Ubuntu 22.04 (Jammy), which triggers a chain reaction preventing the Python virtual environment from being created. ``` The following packages have unmet dependencies: python3-venv : Depends: python3.10-venv (>= 3.10.4-1~) but it is not going to be installed Depends: python3 (= 3.10.4-0ubuntu2) but 3.10.6-1~22.04.1 is to be installed E: Unable to correct problems, you have held broken packages. ``` The user's system has an upgraded python3 package (3.10.6-1~22.04.1), but APT is either holding packages or trying to resolve python3-venv against the base release version (3.10.4-0ubuntu2). Because of this conflict, python3-venv fails to install. On Debian/Ubuntu, Python requires python3-venv / python3.10-venv (specifically `ensurepip`) to initialize virtual environments. Because step 1 failed, Python aborts without creating the venv. `activate` script is missing: Because the virtual environment was never created, `/opt/auto-cpufreq/venv/bin/activate` does not exist. When the user subsequently executes auto-cpufreq (which is a wrapper script `scripts/auto-cpufreq-venv-wrapper`), line 15 fails immediately: ``` . "$venv_bin_dir/activate" # -> /opt/auto-cpufreq/venv/bin/activate: No such file or directory ``` This error doesn't have to do anything with auto-cpufreq. Instead you need to fix the system APT dependencies and reinstall: ``` # Update package indices and upgrade packages to resolve version mismatches sudo apt update sudo apt --fix-broken install sudo apt upgrade -y # Explicitly install the python3 venv package for Python 3.10 sudo apt install -y python3.10-venv python3-venv # Re-run the auto-cpufreq installer sudo ./auto-cpufreq-installer --install ``` Alternatively, you can always [install using Snap](https://github.com/AdnanHodzic/auto-cpufreq#snap-store), but then you won't have the GUI due to its restrictions. @Alen-Issac-Cherian before anything, make sure you have latest git changes, that GUI doesn't look up2date ...

lucasleocs:

Thanks for pointing this out. I opened #975 to address the auto-cpufreq side of this failure mode. It does not try to repair the broken or mismatched APT state itself, but the source installer now stops immediately if dependency installation or virtual-environment creation fails. This prevents it from continuing past a failed step and eventually reporting a successful installation while` /opt/auto-cpufreq/venv `does not exist. #975 also adds version metadata to GitHub source archives. If merged, future releases containing these changes can be installed from an extracted `.zip` or `.tar.gz` archive without requiring Git history (`sudo ./auto-cpufreq-installer`). I validated these fixes on Linux Mint 22.3 using both a normal Git checkout and a GitHub-generated source archive without `.git`.
