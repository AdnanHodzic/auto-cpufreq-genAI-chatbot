fix: apply frequency limits after turbo updates

Issue #930

Description

## Summary - stop short-circuiting `set_frequencies()` based only on power-supply state - read current CPU min/max frequency values on each `set_frequencies()` call - only reapply frequency limits when the live values differ from the desired values ## Why On Intel systems, `scaling_max_freq` can remain stuck at a stale non-turbo cap even after turbo has been enabled. Refreshing limits on turbo changes helped, but it was still possible for the live policy max frequency to drift out of sync while the system stayed on the same power source. ## Result `set_frequencies()` now validates the live frequency values each run and repairs them when needed, so stale low `scaling_max_freq` caps are corrected even without a charger-state transition.
