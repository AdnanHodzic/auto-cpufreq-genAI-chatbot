Fix unsafe stat checks

Pull Request #952

Description

I noticed when testing the Debian packaging PR that my stats and daemon were crashing. Turns out the system I was testing on reported core usage for each CPU core, but only returned 1 frequency. We assumed that the two always matched, but apparently that's not always the case. So, this is just a simple fix to ensure that doesn't happen. I also went ahead and added a guard against a potential (but of course unlikely) division by zero and added a couple of try/except blocks, that again, probably aren't really needed, but are nice to have.
