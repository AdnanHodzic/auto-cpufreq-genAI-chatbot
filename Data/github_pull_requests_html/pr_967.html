fix: Align project licensing with GPL-3.0-or-later

Pull Request #967

Description

## Summary Align the repository's license declarations with the project's intended GPLv3 licensing. The repository had accumulated inconsistent license information over time: * `pyproject.toml` already declared `GPL-3.0-or-later`; * the root `LICENSE` contained the GNU LGPL v3 text; * Nix declared an LGPL license; * Snap declared an LGPL license; * the GTK About view displayed `LGPL3`. As clarified in the discussion below, auto-cpufreq was originally released under GPL 3 and `pyproject.toml` reflects the intended `GPL-3.0-or-later` semantics. ## Changes * Replace the root LGPLv3 license text with the GNU GPLv3 license text. * Change Nix metadata to `lib.licenses.gpl3Plus`. * Change Snap metadata to `GPL-3.0+`, the corresponding GPLv3-or-later form supported there. * Update the GTK About view to display `GNU GPL v3 or later`. * Keep the existing `GPL-3.0-or-later` declaration in `pyproject.toml` unchanged. No README license section is added; the root `LICENSE` remains the canonical license document. ## Validation * Verified that no LGPL metadata remains outside the GPL license text itself. * `python3 -m compileall -q auto_cpufreq`: PASS * `git diff --check`: PASS * Linux Build: PASS * Nix Flake: PASS
